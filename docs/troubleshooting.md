# 운영 트러블슈팅 기록 (2026-09-02 이후)

네 건 모두 공통 원칙: 증상을 덮지 않고 원인을 찾는다. 고친 뒤에는 같은 부류가 다시 오면
사람보다 테스트가 먼저 잡도록 `./check_project.sh test` 항목에 넣는다.

## 1. 검색 한 번에 3.1초, 동시 접속 시 Riot 예산 소진

- 증상: 소환사 검색 응답이 약 3.1초. 여러 명이 같은 시간에 검색하면 Riot API 429.
- 원인: `/api/summoner` 가 요청마다 Riot API 를 새로 호출했다. 같은 소환사를 다시 봐도 전부 재호출.
- 재현: 같은 소환사를 5초 간격으로 두 번 검색하고 서버 로그의 외부 호출 횟수를 센다(수정 전에는 두 번 다 호출).
- 해결: 소환사 단위 5분 캐시 — `web/app.py` 의 `_SUMMONER_CACHE` / `SUMMONER_TTL = 300`. 200건을 넘으면 만료분을 정리한다.
- 결과: 첫 조회 3.1초 → 캐시 적중 0.007~0.02초. 5분 안 재조회는 외부 호출 0.
- 재발 방지: 계약은 `docs/serving.md` 에 적혀 있고, 캐시 만료 전 재조회가 외부를 호출하지 않는지 스모크에서 확인한다.

## 2. 새벽 수집기가 돌면 라이브 검색이 429 로 죽는다

- 증상: 랭킹·챔피언 통계 수집기(`src/collect_ranking.py`, `src/collect_champion_stats.py`)가 도는 동안 라이브 검색이 429.
- 원인: 수집기와 서비스가 같은 API 키의 예산(100회 / 120초)을 나눠 쓴다. 수집기가 예산을 다 쓰면 사용자 몫이 없다.
- 재현: 수집기를 켠 채로 서비스에서 검색 → 429. Riot 응답 헤더 `X-App-Rate-Limit-Count` 로 사용량을 확인한다.
- 해결: `src/riot_api.py` 가 마지막 응답의 사용량을 `LAST_APP_COUNT` 에 남기고, 수집기는 그 값이 `RESERVE = 70` 을 넘으면 20초씩 쉰다. 즉 예산 100 중 수집기는 30만 쓰고 나머지는 사용자 몫.
- 결과: 밤샘 수집 중에도 검색이 정상. 수집 속도는 느려지지만 서비스가 먼저다.
- 재발 방지: 두 수집기가 같은 `RESERVE` 기준을 쓴다(주석으로 서로를 가리킴). 새 수집기를 만들면 같은 양보 규칙을 넣는다.

## 3. 배포했는데 화면이 그대로다

- 증상: 서버를 재시작해도 브라우저에 옛 화면이 보인다. 새로고침해도 같다.
- 원인: HTML 응답에 캐시 헤더가 없어 브라우저가 이전 HTML 을 계속 썼다. 서버 파일과 화면이 달랐다.
- 재현: `curl -sI https://p4.sumzip.com/ | grep -i cache-control` 이 비어 있으면 이 상태다.
- 해결: `web/frontend.py` 의 `after_request` 한 곳에서 `text/html` 응답에 `Cache-Control: no-store, must-revalidate` 를 붙인다.
- 결과: 배포 즉시 반영. 배포 확인은 로컬 파일과 라이브 응답의 바이트 수가 같은지로 한다(`docs/deploy.md`).
- 재발 방지: 배포 절차에 "로컬 = 라이브 바이트 동일" 확인을 넣었다.

## 4. 태그 "0223" 유저 링크가 죽고, 19자리 경기 ID 끝자리가 바뀐다

- 증상: 라이엇 태그가 `0223` 인 유저의 링크가 `223` 으로 나가 404. 승부예측 탭의 19자리 경기 ID 가 브라우저에서 끝자리가 달라진다.
- 원인: CSV → JSON 변환(`web/app.py` 의 `_csv`)이 숫자처럼 보이는 열을 전부 숫자로 바꿨다. `0223` 은 앞 0 이 사라지고, 19자리 ID 는 JS 안전 정수 한계(2^53)를 넘어 정밀도를 잃는다.
- 재현: `/api/ranking` 응답에서 `tag` 가 문자열이 아닌 행을 찾는다. `/api/schedule` 의 `match_id` 를 JS `Number()` 로 바꾸면 값이 달라진다.
- 해결: 문자열로 남길 열을 `TEXT_COLUMNS` 에 명시(`tag`, `name`, `match_id`, `team1_code` 등).
- 결과: 링크·투표 대상이 어긋나지 않는다.
- 재발 방지: `tests/test_contract.py` 가 `tag`·`name` 의 타입을 검사한다. 배포 전 자동 검증(`./check_project.sh test`) 항목에 포함.
