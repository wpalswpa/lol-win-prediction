공통 화면 설계

독립 화면(SCR-H · SCR-T · SCR-C · SCR-R · SCR-V)이 모두 그 안에서 그려지는 프레임과, 화면들이 같은 이름으로 다시 쓰는 공통 요소를 정의한다. 요소마다 어느 화면(SCR)이 쓰고 어느 유스케이스·액티비티(UC · AD)에서 왔는지 붙여 두었다. 독립 화면은 여기 정의된 클래스명·문구·상태를 그대로 구현한다.

3 · 카탈로그

공통 요소 카탈로그

독립 화면이 다시 쓰는 요소 23개. 각 카드는 실제 렌더 · 쓰는 화면(SCR) · 온 곳(UC · AD) · 지켜야 할 규칙을 담는다. 화면 그룹으로 걸러 보면 그 화면을 설계할 때 가져다 써야 할 요소만 남는다.

4 · 추적

요소 ↔ 화면 ↔ 유스케이스 참조 매트릭스

금색 점은 그 화면 그룹에서 핵심으로 쓰이는 요소, 파란 점은 함께 쓰이는 요소다. 독립 화면 설계서는 이 표의 자기 열에 있는 요소를 빠짐없이 구현하고, 새 요소가 필요하면 먼저 여기에 추가한다.

화면 그룹이 참조하는 공통 요소 수. 소환사 복기(SCR-H)가 가장 많은 요소를 쓰므로 공통 요소가 바뀌면 SCR-H 부터 회귀 확인한다.

5 · 상태

공통 상태와 문구

여러 화면이 같은 모양으로 쓰는 상태다. 문구는 UI_00 §6 과 같고, 예외흐름 번호로 UC 문서에 연결된다. 독립 화면은 문구를 바꾸지 말고 그대로 쓴다.

6 · 규칙

독립 화면이 공통 요소를 참조할 때의 규칙

UI_00 §8 의 규칙 가운데 공통 요소에 직접 닿는 것과, 이 문서를 참조하는 방법이다.

R-01

같은 이름을 쓴다

토큰(--blue 등)·클래스(.tile · .verdict · .msg …)·문구를 이 문서의 이름 그대로 쓴다. 새 이름을 만들지 않는다.

근거: index.html 원본 · UI_00 §1 일관성 규칙
R-02

추적표를 붙인다

독립 화면 설계서에는 SCR → CMP → UC/AD 표를 둔다. 공통 요소가 아닌 화면 고유 요소는 SCR-Hn-Ex 처럼 화면 아래 번호를 매긴다.

근거: UI_00 §3 "대응 활동" 열 · 사용자 주의사항
R-03

되지 않는 기능은 숨긴다

riot_ready 가 false 면 검색 바를 비활성하고 이유를 적는다. 눌러도 안 되는 버튼을 두지 않는다.

근거: UC14 7단계 · docs/deploy.md · BR-KEY
R-04

화면은 계산하지 않는다

승률 뒤집기·구간 경계·판정은 서버가 준 값(my_win_prob · band · verdict)을 그대로 보인다. 화면에 숫자 경계를 적지 않는다.

근거: docs/serving.md §6 · BR-PRD-06
R-05

상태 4종을 모두 그린다

데이터가 오는 모든 영역은 불러오는 중 · 빈 결과 · 오류 · 정상 네 상태를 CMP-12 ~ CMP-14 로 그린다. 상태 문구는 §5 표를 따른다.

근거: UI_00 §6 · 각 UC 예외흐름
R-06

두 테마에서 판정색이 구분된다

우세승·역전승은 파랑, 역전패·열세패는 빨강. 역전패는 테두리와 굵기로 한 단계 더 강조한다. 밝음·어둠 모두에서 대비를 확인한다.

근거: .v-* 클래스 · docs/product.md §1
R-07

스냅샷에는 갱신 시각

수집기(UC9 · UC10)가 만든 표를 보이는 화면은 메타 줄에 갱신 시각과 출처 설명을 반드시 넣는다.

근거: BR-LDR · BR-VOT · BP-2
R-08

접근성 속성 유지

탭은 role=tab · aria-selected, 펼침 버튼은 aria-expanded, 칩은 aria-pressed, 페이지 버튼은 aria-current. 포커스 링을 지우지 않는다.

근거: index.html 현재 구현 · UI_00 §8 (기준치는 자료 없음 — 확인 필요)
