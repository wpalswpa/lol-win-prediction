유저 전적 분석 화면 설계

홈 탭의 첫 다섯 화면 — 검색 바(H1) → 조회 진행(H2) → 프로필 카드(H3) · 판정 타일+COACH(H4) · 플레이 성향(H5) — 을 SCR-00 공통 프레임 안에서, 비즈니스 프로세스 BP-1 의 활동(AD-3)이 기능 요소로 전개되는 순서대로 설계한다. 다섯 화면은 하나의 API 응답(POST /api/summoner)을 나눠 그리는 한 시스템의 영역들이므로, 상태 하나·데이터 하나·슬롯 하나의 통합 계약을 먼저 정하고 각 화면을 그 안에 넣었다.

H1
소환사 검색 바 = CMP-05공통 프레임의 검색 바가 그대로 H1 이다. 새 요소를 만들지 않고 riot_ready 상태·형식 검사만 화면 규칙으로 더한다.
H2
조회 진행 = CMP-12 + 문장회전 표시는 공통, 문장은 H2 고유. Riot ID 를 문장에 넣어 "무엇을 기다리는지"를 말한다. 성공하면 H3~H5 가 이 자리를 대체한다.
H3
프로필 카드 — 누구인가rank · radar · lane 을 한 카드에. 3판 미만이면 레이더·라인 기준선이 비고 카드는 좁아진다. 티어 색은 CMP-21 관례.
H4
진단 먼저, 지표는 그 다음COACH 요약(한 줄 진단 + 자기평가)이 타일보다 위에 온다. 타일 값은 전부 판정 4종 건수에서 파생한다(§5 차트).
H5
성향은 복기 재료예측에 쓰지 않는다는 주의 문구가 항상 붙는다. 더 보기(H9)로 페이지가 늘면 화면이 합산해 다시 그린다.
S

통합 규칙

I-01

응답 하나, 영역 다섯

POST /api/summoner 응답 한 번으로 H3(rank · radar · lane) · H4(건수 · 평균 · 적중) · H5(style) · H7(games) 를 모두 그린다. 영역별로 따로 부르지 않는다. 필드가 없으면 그 영역만 비운다.

근거: UI_00 §3 "호출 API" · docs/serving.md "/api/summoner 응답"
I-02

상태 변수는 하나

홈 영역의 표시 여부는 S0~S7 하나로 정한다. 영역이 각자 자기 상태를 갖지 않는다. 새 화면(H6~H10)을 붙일 때도 이 상태에 매핑한다 — H7 은 S4·S5, H10 은 S0·S2·S6·S7.

근거: §2 통합 목업 · SCR-00 R-05 "상태 4종을 모두 그린다"
I-03

슬롯 ID 를 고정한다

H1 #searchrow · H2/H10 #rows 상단 · H3 #profile · H4 #brief + #tiles · H5 #styleBox. 렌더 함수는 자기 슬롯만 채운다. 순서는 위에서 아래로 고정(프로필 → 요약 → 성향 → 행).

근거: index.html renderProfile · renderSummary · 슬롯 ID
I-04

화면은 나누기만 한다

판정(우세승 등) · 구간(band) · 승률 방향(my_win_prob) · 레이더 백분위 · 라인 등급은 서버 값이다. 화면은 건수를 비율로 바꾸는 것(H4-05)과 여러 페이지 합산(H5-05)만 한다. 이 두 계산은 서버 규칙과 같은지 검수 항목에 넣는다.

근거: SCR-00 R-04 · BR-SUM · coach.style_summary
I-05

동시 요청을 막고 늦은 응답을 버린다

loading 이 참이면 분석 버튼·Enter·이름 클릭을 무시한다. 요청마다 seq 를 올리고, 응답이 도착했을 때 최신이 아니면 그리지 않는다. 탭 전환·다른 소환사 클릭이 섞여도 영역이 뒤섞이지 않는다.

근거: index.html loadSummoner 의 loading · seq
I-06

공통 요소는 이름을 바꾸지 않는다

CMP-05 · 10 · 12 · 13 · 14 · 16 · 17 · 21 · 22 · 08 · 09 를 SCR-00 클래스명 그대로 쓴다(.searchrow · .btn.primary · .spin · .empty · .msg · .tile · .verdict · .tierbadge · .num · .note · details.box). 화면 고유 요소는 .profile · .pf-* · .brief · .selfnote · .stylerows · .strow · .lanebase 를 쓴다.

근거: SCR-00 R-01 "같은 이름을 쓴다"
I-07

탭 전환은 숨김이지 파괴가 아니다

다른 탭으로 가면 H1~H5 를 숨기고, 돌아오면 마지막 상태(S4 등)를 그대로 보인다. 재조회하지 않는다. 다만 다른 탭에서 이름을 클릭해 돌아오면 그것은 UC3 새 시작이므로 S3 부터다.

근거: SCR-00 CMP-04 · UI_00 §8 "이름 클릭은 화면 이동"
I-08

3판 미만은 조용히 줄인다

레이더 · 라인 기준선 · 성향 블록은 "표본 부족" 안내 대신 영역을 없앤다. 대신 H4 조회 범위 줄이 "최근 n판"을 말하므로 이용자는 판수를 안다. 빈 상자·"—" 로 가득한 상자를 남기지 않는다.
